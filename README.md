# finground-lite-kr

한국어 · [English](README.en.md)

기사·리포트·AI 답변 속 **한국 상장사 재무 수치를 DART 공시 원값으로 검증**하는 Claude Code 플러그인입니다. "삼성전자 2분기 영업이익은 10조4천억원으로 전년 동기 대비 15% 증가"처럼 숫자가 든 문장을 주장 단위로 쪼개, 각 숫자가 공시와 맞는지, 틀렸다면 **어떤 흔한 실수와 일치하는지**(별도 기준, 누적값, 전년 동기, 지배주주 순이익, 억/조 단위 …)를 접수번호와 함께 알려 줍니다.

- **모델은 계획만, 판정은 코드가.** LLM은 문장을 "회사·지표·기간·원문 구간"으로 된 검증 계획으로 바꾸기만 합니다. 숫자 읽기, 공시 조회, 공식 계산, 판정, 출처 첨부는 전부 결정적 코드가 합니다. [VeriFin](https://arxiv.org/abs/2608.10213)의 원칙(주장은 사실·공식 확정에 영향을 주지 못한다, 근거가 없으면 보류)을 따릅니다.
- **판정은 셋.** 지지 / 모순 / 보류. 보류는 "틀렸다"가 아니라 "확정할 근거가 없다"입니다(보고서 미제출, 회사 미확정, 모호한 표현).
- **한국 공시 함정 진단.** 연결/별도, 분기·반기보고서의 3개월 열과 누적 열, 당기순이익과 지배주주 순이익, 전년 동기·직전 분기, 억·조 단위, 손익 부호, 증감률 계산 착오, %p와 % 혼동.
- **표준 라이브러리만.** 설치할 패키지가 없습니다. DART 키는 사용자가 직접 발급해 환경변수에 넣습니다. 키를 저장하거나 출력하지 않습니다.

> 비공식 구현이며 논문 저자들과 관계가 없습니다. "지지"는 공시값과의 일치이지 공시 자체의 정확성이나 투자 판단이 아닙니다.

## 설치

1. [opendart.fss.or.kr](https://opendart.fss.or.kr)에서 무료 인증키를 발급받아 환경변수에 넣습니다.

   ```powershell
   [Environment]::SetEnvironmentVariable("DART_API_KEY", "<발급받은 키>", "User")
   ```

2. Claude Code에서 플러그인을 설치합니다.

   ```
   /plugin marketplace add sinkytiger/finground-lite-kr
   /plugin install finground-lite-kr@finground-lite-kr
   ```

3. 재무 수치가 든 문장을 붙여 넣고 "공시로 팩트체크해 줘"라고 하면 `factcheck` 스킬이 동작합니다. Python 3.10 이상이 `python`으로 실행돼야 합니다.

Claude Code 없이 쓰려면:

```bash
python -m finground_kr.cli lookup 005930 2026 H1
python -m finground_kr.cli verify plans.json --as-of 2026-08-20
python -m finground_kr.cli serve        # MCP 서버 (stdio)
```

## 동작 예

입력 문장: "삼성전자의 2분기 영업이익은 146조7,252억원이었다" (기사 날짜 2026-08-20)

| # | 판정 | 주장 | 공시 기준값 | 차이 | 진단 | 출처 |
|---|---|---|---|---|---|---|
| c1 | ❌ 모순 | 146조 7,252억원 | 89조 4,924억원 | -57조 2,327억원 | 2026년 상반기 누적 값 (146조 7,252억원) | 2026년 반기보고서 (연결) IS 영업이익 thstrm (접수 20260814003699) |

2분기(3개월) 영업이익 자리에 상반기 누적값을 쓴 문장입니다. 허용 오차는 주장이 쓴 마지막 자릿수의 절반이며, 기본 모드는 반올림과 절사를 모두 인정하고 절사는 따로 표시합니다. 엄격 모드(`mode: "strict"`)는 반올림만 인정합니다.

## 무엇을 검증하나 (v1)

| 유형 | 지표 | 기간 |
|---|---|---|
| 수치 | 매출액, 매출원가, 매출총이익, 영업이익, 당기순이익, 지배주주 순이익, 자산·부채·자본총계, 지배주주 자본 | 분기(3개월), 상반기·3분기 누적, 4분기(연간 − 3분기 누적), 연간, 분기 말 |
| 비율 | 영업이익률, 순이익률, 매출총이익률, 부채비율, 자기자본비율 | |
| 비교 | 전년 동기·직전 분기·전년 말 대비 증감률, 증감액, %p 변화, 늘었다/줄었다, 흑자·적자 전환 | |

전년 동기 값은 같은 보고서의 비교 열(회사가 재작성한 비교치)을 우선 씁니다. 기사 날짜 이후 제출된 보고서는 보이지 않습니다. 금융업(계정 체계가 다름), 12월 결산이 아닌 회사, 주가·시가총액·배당, 정정 전 수치, 잠정실적은 v1 범위 밖이며 보류됩니다.

## 평가

### E1. 검증기 단독 (정답 계획 입력)

공시값에서 거꾸로 만든 벤치마크로 측정했습니다. 비금융 대형주 16개사(삼성전자, 현대자동차, SK하이닉스, NAVER, 카카오, LG전자, 기아, 현대모비스, POSCO홀딩스, LG화학, 삼성SDI, 삼성바이오로직스, KT, SK텔레콤, 삼성물산, LG에너지솔루션)의 2024 FY~2026 H1 공시에서 문장 14,056개를 만들었고, 그중 11,471개에 함정 오류를 넣었습니다. 라벨은 허용 오차 규칙만으로 정하며 검증기는 라벨 생성에 관여하지 않습니다. 지표는 VeriFin과 같습니다.

| 모드 | n | 맞는 주장 지지(TA) | 틀린 주장 지지(FA) | 틀린 주장 기각(TR) | 맞는 주장 기각(FR) | 보류 | 수용 정밀도 | 정확도 | 커버리지 |
|---|---|---|---|---|---|---|---|---|---|
| 기본 (반올림·절사) | 14,056 | 2,585 | 0 | 11,279 | 0 | 192 | 100% | 100% | 98.6% |
| 엄격 (반올림만) | 14,056 | 2,184 | 0 | 11,680 | 0 | 192 | 100% | 100% | 98.6% |

- 보류 192건은 모두 이익률 변화를 %p 대신 %로 쓴 문장입니다. 상대 증감률인지 %p 차이인지 모호해 두 해석의 값을 보여 주고 판정하지 않습니다.
- 함정 진단: 기대 진단이 있는 7,434건 중 7,319건(98.5%)에서 해당 해석을 찾았습니다. 누락은 전부 "3조 500억원"처럼 100억 단위로 반올림한 표기에서 다른 해석과의 차이가 허용 오차를 조금 넘긴 경우입니다. 근접 오류(값에 ±1~5%) 3,845건 중 187건(4.9%)은 다른 해석과 우연히 겹쳐 진단이 붙었습니다. 진단은 "일치하는 다른 해석"의 목록이지 단정이 아닙니다. 진단 범위를 상대 오차 2%로 넓히면 적중이 98.7%로 오르는 대신 허위 진단이 23%로 뛰어 채택하지 않았습니다.
- 엄격 모드에서 TA가 줄어든 것은 절사 표기가 그 모드의 정의상 틀린 주장이 되기 때문입니다.

이 숫자는 **템플릿 문장**에서 나온 것입니다. 생성기와 검증기가 같은 공시 열 해석을 공유하므로, 이 실험은 "검증기가 설계대로 동작하는가"를 보여 줄 뿐 실제 기사에서의 성능이 아닙니다. 전체 표: [reports/e1_kr16.md](reports/e1_kr16.md) (삼성전자만: [reports/e1_samsung_fixture.md](reports/e1_samsung_fixture.md)), 벤치마크 설명: [docs/benchmark.md](docs/benchmark.md). 공시 녹화본은 `bench/fixtures/dart`에 있어 네트워크 없이 재현됩니다.

### E2·E3. LLM이 들어간 실험 (Opus 5.5, 삼성전자 문장 45개)

삼성전자 벤치마크에서 맞는 문장 26개, 틀린 문장 20개(함정 9종), 복합 문장(수치 + 증감률) 6개를 뽑아 Claude Opus 5.5로 실험했습니다. 모델은 Claude Code 안에서 서브에이전트로 실행했고, 검증 도구나 DART 조회 없이 각 과제 파일만 보고 답했습니다.

| 실험 | 무엇을 했나 | n | TA | FA | TR | FR | 보류 |
|---|---|---|---|---|---|---|---|
| E2 계획 작성 → 검증기 | Opus가 스킬 지침대로 계획을 쓰고 검증기(기본 모드)가 판정 | 45 | 25 | 0 | 20 | 0 | 0 |
| E3 LLM 판정자 | 같은 공시 표를 받은 Opus가 직접 판정 (반올림만 허용 규칙) | 39 | 15 | 1 | 23 | 0 | 0 |
| E3′ LLM 판정자 + 공식 | E3에 허가된 공식과 피연산자 값을 추가로 제공 | 39 | 15 | 1 | 23 | 0 | 0 |

- E2: 45문장 모두 올바른 결론에 도달했습니다. 복합 문장 6개는 모두 두 계획으로 나뉘었고, "지배주주 순손실" 문장은 지표 span의 손실 표현으로 부호가 잡혔습니다. 모델이 숫자를 변환하지 않고 원문 구간만 넘기는 설계가 그대로 동작했습니다.
- E3: Opus 판정자는 심은 함정 20건을 **모두 기각**했습니다. 수용 오류 1건은 절사 표기("523조 6,595억원", 실제 523조 6,595억 8,600만원이라 반올림하면 6,596억)를 규칙상 틀렸는데도 받아들인 경우로, 공식을 줘도 같았습니다. VeriFin에서 Claude Haiku 4.5 판정자가 틀린 주장 92개 중 75개를 통과시킨 것과 달리, 이 실험의 함정은 더 거칠고(배수·기간·기준 착오) 모델이 더 강해 재현되지 않았습니다. 표본이 39개라 효과를 추정할 수는 없고, 근접 오류(±1~5%)나 실제 기사 문장에서의 차이는 다음 과제입니다.
- 결과 파일: [reports/llm_samsung_fixture.md](reports/llm_samsung_fixture.md), 과제와 답변: `bench/llm/`.

## 구조

```
finground_kr/
  numbers.py     한국어 금액·비율·증감 표현 파서, 허용 오차 규칙 (반올림/절사/완곡/범위/경계)
  dart.py        DART OpenAPI 클라이언트 (키는 환경변수에서만), 디스크 캐시, 오프라인 모드
  facts.py       지표 레지스트리, 기간 산술 (3개월·누적·4분기·TTM·비교 열), 사실 바인딩과 출처
  verify.py      계획 검사 → 사실 바인딩 → 공식 → 판정
  diagnose.py    함정 해석 대조
  mcp_server.py  MCP 서버 (stdio, 표준 라이브러리)
  cli.py         명령줄
skills/factcheck/SKILL.md   Claude가 따르는 절차와 계획 형식
bench/           벤치마크 생성 (generate), E1 평가 (evaluate), LLM 실험 묶음 (packets)
tests/           녹화한 DART 응답으로 도는 테스트 (네트워크 없음)
docs/            설계, 논문 분석, 벤치마크 설명
```

테스트: `pip install -e ".[dev]" && pytest -q`
