# 설계안: 공시 팩트체커 (finground-lite-kr)

한국어 기사·리포트·AI 답변 속 재무 수치 주장을 DART 원값으로 검증하는 Claude Code 플러그인입니다. Opus는 문장을 검증 계획으로 바꾸는 일만 하고, 수용 여부는 코드가 DART 원값과 공식으로 결정합니다.

> 2026-10-09 작성. v1 구현 완료 후 달라진 점은 본문에 표시했습니다. 결과는 [README](../README.md)와 [reports/](../reports/)에 있습니다.

## 1. 근거 논문

| | FinGround ([arXiv 2604.23588](https://arxiv.org/abs/2604.23588)) | VeriFin ([arXiv 2608.10213](https://arxiv.org/abs/2608.10213)) |
|---|---|---|
| 문제 | 금융 답변의 환각 탐지와 수정 | LLM이 만든 숫자 주장을 받아들여도 되는가 (acceptance control) |
| 방법 | 원자 주장 분해 → 6유형 분류 → 유형별 검증(계산은 공식 47개로 재계산) → 셀 단위 인용으로 수정 | LLM은 검증 계획만 작성, 값은 XBRL 공시값에 바인딩, 공식은 질문·calculation linkbase·지표 레지스트리에서만 허가, Z3로 판정 |
| 판정 | 지지 / 모순 / 검증 불가 | Verified / Violated / Abstain |
| 핵심 결과 | 환각률 4.1%(GPT-4o+CoT 대비 78%↓). 계산 주장의 환각률이 가장 높음(28.4%) | 틀린 주장 수용(false accept) 0건. 기준선은 92건 중 6~92건을 수용. 정답 공식과 피연산자를 줘도 LLM 판정자는 75건을 수용 |
| 한계 | 영어 SEC만. 학습 모델 4개. 공식 코드 링크 404 | 영어 10-K만. 맞는 주장도 37~73건 기각(보수적). 코드 공개됐으나 라이선스 미지정 |

이 프로젝트가 가져오는 것:

- VeriFin: 주장과 독립적으로 사실·공식을 확정하는 원칙, 3-판정(보류 포함), 오차 = 표기 정밀도의 절반 단위, 수용 통제 지표(TA/FA/TR/FR/Abs), 검증기 진단을 이용한 수정과 재검증, 공시값에서 거꾸로 문항을 만드는 벤치마크 구성법
- FinGround: 주장 유형 분류, 계산 주장의 공식 재구성, 출처 인용, "원문은 X인데 주장은 Y" 형태의 설명

VeriFin 코드는 라이선스가 없어 사용하지 않습니다. 모든 구현은 새로 작성합니다.

## 2. 차별점

알려진 범위에서 한국어 문장의 숫자 주장을 DART 원값으로 판정하는 공개 도구는 찾지 못했습니다(2026-10-09 검색). 기존 DART MCP 서버들은 조회 도구이고, korean-dart-mcp의 합산 검증은 공시 자체의 내부 일관성 검사입니다.

1. **한국 공시 함정 진단.** 틀린 주장이 어떤 다른 해석과 일치하는지 찾아 알려 줍니다. 대상은 별도 기준, 누적 vs 3개월, 전년 동기, 직전 분기, 비지배지분 포함 순이익, 단위(억·조), 정정 전 수치입니다. VeriFin의 UNSAT core 역할을 합니다.
2. **문장 근거 고정 파싱.** Opus가 뽑은 필드마다 원문 구간을 인용하게 하고, 코드가 그 구간을 다시 해석해 값이 맞는지 확인합니다. 불일치하면 보류합니다. LLM 파싱 오류가 거짓 수용으로 이어지는 경로를 막습니다.
3. **기준일 처리.** 기사 날짜 기준으로 그때까지 제출된 보고서만 씁니다. 정기보고서가 아직 없으면(잠정실적 단계) 보류하고 이유를 적습니다.
4. **배포 형태.** Claude Code 플러그인이라 Max·Pro 사용자는 추가 비용 없이 씁니다.

## 3. 동작 흐름

```
기사 문장 (+ 기사 날짜)
   │
   ▼  [Opus · 스킬]  검증 계획 작성: 주장마다 회사·기간·기준·지표·값·비교 대상 + 원문 구간
   │
   ▼  [코드 · MCP 도구 verify_claims]
   │    1) 계획 검사: 원문 구간을 규칙으로 다시 해석해 필드와 대조 → 불일치면 보류
   │    2) 사실 바인딩: DART 원값 (기준일 이전 제출분만), 값은 주장과 무관하게 공시에서만
   │    3) 공식 허가: 주장 문구("전년 동기 대비") → 지표 레지스트리 → 없으면 보류
   │    4) 판정: |기대값 − 주장값| ≤ 허용오차 → 지지 / 초과 → 모순 / 근거 부족 → 보류
   │    5) 진단: 모순이면 함정 해석들과 대조해 일치하는 것을 보고
   │    6) 인용: 접수번호·보고서·재무제표·계정·열(3개월/누적)·DART 링크
   ▼
[Opus · 스킬]  표로 보고. 원하면 모순 주장만 근거와 함께 고쳐 쓰고, 고친 문장은 다시 verify_claims로 검증
```

## 4. 검증 계획 형식 (Opus 출력)

```json
{
  "id": "c1",
  "quote": "2분기 영업이익은 10조4천억원으로 전년 동기 대비 15% 증가했다",
  "company": {"name": "삼성전자", "span": "삼성전자"},
  "kind": "value | change | direction",
  "metric": {"id": "operating_income", "span": "영업이익"},
  "period": {"year": 2026, "period": "Q2", "scope": "quarter", "span": "2분기"},
  "basis": {"value": "CFS", "span": null},
  "value": {"span": "10조4천억원"},
  "change": {"type": "growth_pct", "span": "15% 증가", "compare": "yoy"},
  "hedge_span": null
}
```

- `scope`: `quarter`(3개월) / `cumulative`(누적) / `annual` / `point`(재무상태표 기말)
- 기준(`basis`)이 문장에 없으면 연결(CFS)로 두고, 판정에 "기준 미기재"를 표시합니다.
- 숫자는 Opus가 변환하지 않고 원문 구간만 넘깁니다. 변환은 코드가 합니다.

| 유형 (FinGround) | v1 | 내용 |
|---|---|---|
| 수치 | ✅ | 매출액, 영업이익, 당기순이익, 지배주주 순이익, 자산·부채·자본총계, 지배주주 자본 |

## 6. 허용 오차와 보류 규칙

- **오차**: 주장 표기 정밀도의 절반 단위(VeriFin과 같은 원칙). "10조원"이면 ±0.5조, "10조4천억원"이면 ±500억, "8.3%"면 ±0.05%p
- **절사 허용**(설정): 국내 기사는 반올림 대신 절사하는 경우가 많아, 기본값은 반올림 또는 절사 중 하나로 맞으면 지지하고 "절사"를 표시합니다. 논문식 엄격 모드(반올림만)도 제공해 두 결과를 함께 보고합니다.
- **완곡 표현**("약", "가량", "수준", "육박"): 한 단위까지 허용하고 표시합니다. FinGround는 오탐의 52%가 완곡 표현에서 나왔다고 보고합니다.
- **보류**: 회사 미식별, 기간 모호, 계정 없음, 보고서 미제출(기준일), 공식 미허가, 원문 구간과 계획 불일치. 보류는 "틀렸다"가 아니라 "확정할 근거가 없다"로 보고합니다.

## 7. 함정 진단 목록

모순 판정 시 아래 해석으로 다시 계산해, 허용 오차 안에서 **하나만** 일치할 때 "~와 일치"로 보고합니다. 여러 개가 맞으면 후보를 모두 적고 단정하지 않습니다.

| 진단 | 예 |
|---|---|
| 별도 기준 값 | 연결이라 썼지만 별도 영업이익과 일치 |
| 누적 값 | "2분기"라 썼지만 상반기 누적과 일치 |
| 전년 동기 / 직전 분기 값 | 기간 착오 |
| 비지배지분 포함 순이익 | "지배주주 순이익"이라 썼지만 연결 당기순이익과 일치 |
| 단위 착오 | 10배·1만 배 차이(억↔조 등) |
| 정정 전 수치 | 정정공시 이전 원래 보고서 값과 일치 — **v1 미구현** (DART 재무제표 API는 정정본만 돌려주므로 원본 XBRL을 따로 받아야 함) |
| 증감률 계산 착오 | 증감액을 비율로, 누적끼리 비교, 분모를 당기로 계산 |
| %와 %p 혼동 | 이익률 변화를 %로 표기 |

## 8. 구조

```
finground-lite-kr/
  .claude-plugin/plugin.json, marketplace.json
  .mcp.json                     # 표준 라이브러리 MCP 서버 실행
  skills/factcheck/SKILL.md     # Opus 절차: 계획 작성 → verify_claims → 보고 → (선택) 수정·재검증
  finground_kr/
    dart.py        # DART 클라이언트, 캐시, 기준일 필터 (키는 DART_API_KEY 환경변수에서만)
    facts.py       # 계정 매핑, 기간 계산(3개월·누적·4분기·TTM), 사실 바인딩
    numbers.py     # 한국어 금액·비율·기간·완곡 표현 파서
    registry.py    # 지표 공식 레지스트리 (정의와 출처)
    verify.py      # 계획 검사 → 바인딩 → 공식 → 판정
    diagnose.py    # 함정 진단
    cite.py        # 인용 문자열과 DART 링크
    mcp_server.py  # 도구: verify_claims, lookup_facts, list_metrics
  bench/           # 벤치마크 생성·평가
  tests/           # 네트워크 없이 도는 테스트 (녹화한 DART 응답 사용)
  docs/
```

**플러그인 구성 (공식 문서 확인 사항)**

- 키 전달: `.mcp.json`의 `env`에 `"DART_API_KEY": "${DART_API_KEY:-}"`로 사용자 환경변수를 넘깁니다. 서버는 빈 값이나 치환되지 않은 문자열이면 거부합니다. 키를 설정 화면에서 받는 `userConfig`(`sensitive: true`, 보안 저장소 보관) 방식도 함께 지원할지는 구현 때 결정합니다.
- 캐시: 회사 코드표와 DART 응답 캐시는 업데이트 후에도 남는 `${CLAUDE_PLUGIN_DATA}`에 둡니다.
- 도구 이름: 모델에는 `mcp__plugin_finground-lite-kr_dart__verify_claims` 형태로 보입니다. 스킬의 `allowed-tools`로 사전 허용합니다.
- 프로토콜: `initialize` 핸드셰이크 기반 `2025-11-25` 버전을 구현합니다. stdout에는 줄 단위 JSON만 쓰고 로그는 stderr로 보냅니다. 한국어 Windows의 cp949 문제를 피하려고 바이트 단위로 입출력합니다.
- 배포: 같은 저장소에 `marketplace.json`을 두고 `/plugin marketplace add sinkytiger/finground-lite-kr`로 설치합니다. 데스크톱 앱의 Code 탭은 플러그인 설치를 지원하지만, GitHub 마켓플레이스 추가가 화면에서 되는지는 문서에 없어 직접 확인이 필요합니다.

Z3는 쓰지 않습니다. v1의 검사는 공식 하나와 허용 오차 비교라서, 정확한 십진 산술(`decimal`)로 같은 결정을 내립니다. 진단은 UNSAT core 대신 함정 해석 대조로 제공합니다. 설치할 것이 없도록 표준 라이브러리만 씁니다.

## 9. 평가

**벤치마크 (VeriFin의 역방향 구성).** DART 원값에서 시작해 한국어 주장 문장을 만들고, 일부에 함정 오류를 넣어 정답 라벨을 자동으로 붙입니다.

- 비금융 대형주 10개 내외 × 최근 보고서 6~8개, 연결·별도
- 문장 표현 다양화: "1조 2,345억원", "12조3456억", "1.2조", 절사·반올림, 완곡 표현
- 라벨: 정답 / 오류 유형(위 7장 목록 + 값 바꿔치기 + ±1~3% 근접 오류)

**실험**

| 실험 | 비교 대상 | 측정 |
|---|---|---|
| E1 검증기 단독 (정답 계획 입력) | — | 진단 정확도, 보류율 (검증 로직 자체) |
| E2 전체 파이프라인 (Opus가 계획 작성) | E1 | 파싱 오류가 판정에 미치는 영향 |
| E3 같은 근거를 받은 LLM 판정 | Opus 판정자 / Opus 판정자 + 공식·피연산자 (VeriFin의 Judge+Formula) | 거짓 수용 수. VeriFin의 "공식을 줘도 수용" 결과가 재현되는지 |
| E4 수정 | 일반 재시도 vs 진단 기반 수정 | 수정 후 재검증 통과율 |

지표는 VeriFin과 같게 둡니다: TA, FA(거짓 수용), TR, FR(거짓 기각), Abs(보류), 수용 정밀도, 판정 정확도, 커버리지. 여기에 진단 정확도를 더합니다. E2~E4의 Opus 호출은 Claude Code 세션(요금제 사용량)에서 표본 단위로 돌립니다. 다른 사람이 재현할 수 있도록 실행 스크립트와 프롬프트를 저장소에 둡니다.

**실제 기사 표본(선택).** 사용자가 고른 기사 문장으로 소규모 점검을 합니다. 저작권 때문에 기사 원문은 저장소에 넣지 않고 집계만 공개합니다.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 기사 다수가 잠정실적 기준이라 정기보고서 이전에는 보류가 많음 | 보류 사유를 명확히 표시. v2에서 잠정실적 공정공시 파싱 검토 |
| 계정명이 회사마다 다름 | account_id 우선, 한글명 대체, 실패 시 보류. 매핑 실패율을 결과에 보고 |
| 보수적 판정으로 맞는 주장도 기각(VeriFin 37~73건) | 엄격·절사 두 모드 결과를 함께 공개 |
| Opus 사용량 한도 | 벤치마크는 표본 크기를 정해 단계적으로 실행 |
| 회색지대인 자동화 | 평가는 대화형 세션에서 실행. `claude -p` 스크립트는 사용자 선택 |
