# 벤치마크: 공시값에서 거꾸로 만든 한국어 수치 주장

VeriFin의 XBRLFiling처럼 **답에서 문제를 만듭니다.** 회사가 제출한 값에서 출발해 한국어 기사 문장을 만들고, 정답 검증 계획과 라벨을 함께 저장합니다. 사람이 쓴 기사가 아니므로 문체는 단순하지만, 숫자 표기 관행(절사, 천억 단위, 완곡 표현)과 한국 공시의 함정은 실제와 같습니다.

생성: `python -m bench.generate --cache <DART 캐시> --companies <corp_code...> --years 2025 2026 --out bench/data/<name>.jsonl`

## 샘플 구성

한 샘플 = 문장 1개 + 계획 1개(복합 문장은 2개) + 정답값 + 모드별 라벨 + 함정 정보.

| 주장 유형 | 지표 | 기간 |
|---|---|---|
| 수치 (`value`) | 매출, 영업이익, 당기순이익, 지배주주 순이익 / 자산·부채·자본총계 / 영업이익률, 순이익률, 부채비율 | 1~4분기(3개월), 상반기·1~3분기 누적, 연간, 분기 말 |
| 전년 동기 대비 증감률 (`change`, growth_pct) | 금액 지표 | 위와 같음 (비교 기준이 양수일 때만) |
| 전년 동기 대비 증감액 (`change`, diff) | 금액 지표 | |
| 전년 동기 대비 %p (`change`, pp) | 이익률 | |
| 복합 문장 (수치 + 증감률) | 영업이익 | 계획 작성 실험(E2)용 |

4분기 값은 사업보고서 − 3분기 누적으로, 전년 동기는 같은 보고서의 비교 열로 계산합니다(검증기와 같은 규칙이지만 라벨은 검증기를 거치지 않습니다).

## 표기 스타일

| 스타일 | 예 | 비고 |
|---|---|---|
| full_eok / trunc_eok | 89조 4,924억원 | 1억 단위 반올림 / 절사 |
| cheon_eok / trunc_cheon_eok | 89조4천억원 | 천억 단위 반올림 / 절사 |
| baek_eok | 89조 4,900억원 | 100억 단위 반올림 (끝자리 0은 비유효로 취급) |
| jo_1dec / approx_jo_1dec | 89.5조원 / 약 89.5조원 | |
| eok_plain | 894,924억원 | |
| pct_1dec / pct_1dec_trunc / pct_int / pct_int_trunc / approx_pct_int | 52.2% / 52.1% / 52% / 52% / 약 52% | 비율과 증감률 |

손실은 "영업손실 1,200억원"처럼 지표명을 바꿔 씁니다.

## 라벨

라벨은 **허용 오차 규칙만으로** 정합니다(`numbers.consistent`): 문장의 수량이 정답과 표기 정밀도 안에서 일치하면 `correct`, 아니면 `incorrect`. 기본 모드(반올림 또는 절사)와 엄격 모드(반올림만)의 라벨을 따로 둡니다. 절사한 표기는 엄격 모드에서 `incorrect`가 됩니다. 검증기는 라벨 생성에 관여하지 않으므로, 사실 바인딩이나 기간 해석을 틀리면 그대로 오판으로 집계됩니다.

## 함정 (오류 주입)

| 함정 | 만드는 법 | 기대 진단 |
|---|---|---|
| basis_swap | 별도(또는 연결) 값으로 교체 | 별도/연결 기준 값 |
| cumulative_for_quarter | 2·3분기 3개월 값을 누적값으로 | 누적 값 |
| quarter_for_cumulative | 상반기·3분기 누적을 3개월 값으로 | 3개월 값 |
| prior_year / prior_quarter | 전년 동기 / 직전 분기 값으로 | 전년 동기 값 / 직전 분기 값 |
| owners_swap | 당기순이익 ↔ 지배주주 순이익 | 지배기업 소유주지분 순이익 / 비지배지분 포함 |
| unit_x10 / unit_div10 / unit_div100 | 값에 ×10, ÷10, ÷100 | 단위 착오 |
| sign_flip | 이익을 손실로 | 부호 |
| near_miss_0.01/0.02/0.05 | 값에 ±1·2·5% | (진단 없어야 함: 허위 진단률 측정) |
| growth_qoq_base | 전년 동기 대신 직전 분기 기준 증감률 | 직전 분기 대비로 계산한 값 |
| growth_denominator_current | 분모를 당기로 | 분모를 당기 |
| growth_cumulative | 누적끼리 비교한 증감률 | 누적 값 |
| growth_sign | 증감 방향 반대 | 부호 |
| growth_near_miss_0.02/0.05 | 증감률에 ±2·5% | (진단 없어야 함) |
| pp_as_pct | 이익률 변화를 %p 대신 %로 | 보류 (두 해석 제시) |

허용 오차 안에 들어가는 함정(예: 연결과 별도가 거의 같은 경우)은 버립니다.

## 평가 (E1)

`python -m bench.evaluate <jsonl> --cache <캐시> --out reports/e1.md`

검증기에 정답 계획을 넣고 VeriFin 지표로 집계합니다: TA(맞는 주장 지지), FA(틀린 주장 지지), TR, FR, 보류, 수용 정밀도 TA/(TA+FA), 정확도 (TA+TR)/판정 수, 커버리지. 함정별로 진단 적중·누락과 근접 오류의 허위 진단을 함께 셉니다. 진단은 모드와 무관하게 느슨한 허용 오차로 계산합니다(수용 결정이 아니라 힌트이므로).

## 한계

- 문장은 템플릿이라 실제 기사의 복잡한 구문(여러 회사 비교, 인용, 잠정실적 표현)을 담지 못합니다.
- 회사·기간 범위는 캐시된 공시에 따릅니다. 테스트 고정 데이터는 삼성전자 2024 FY~2026 H1 한 곳뿐이므로, 공개할 결과는 여러 회사로 다시 만들어야 합니다.
- 정정 전 수치 함정은 v1에서 만들지 않습니다.
